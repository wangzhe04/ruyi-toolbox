# 08 · 批量数据分析与本地语音输出

> 状态：两条独立的后续路线，均未实施。优先级见 [03](03-expansion-roadmap.md)，候选比较见 [04 §5–6](04-research-and-decisions.md)。下述接口均为拟议契约。

## 1. 批量数据分析：解决可重复计算

目标：“合并几十份月报，按编号关联费用表，找出重复、缺项和金额差异，导出可复算结果。”已有 `data_profile`、Excel 读写和图表工具继续使用；新增组件专注跨文件计算，不再做另一套表格美化。

目录建议 `mcp/data-analysis/`、包 `ruyi_data_analysis`。首版 CSV/TSV、XLSX、Parquet；旧 XLS、宏执行、Office 实时编辑、外部数据库连接留后。DuckDB 为计算内核首选，Polars 为复杂变换备选。

### 1.1 工具与计算契约

| 工具 | 行为 |
| --- | --- |
| `data_import` | 导入明确授权的文件/工作表/范围，返回 datasetId、推断类型、警告和 jobId |
| `data_preview` | 有界取样、列信息、解析失败计数，不能把抽样统计写成全量统计 |
| `data_transform` | 结构化步骤：select/filter/cast/join/group/deduplicate，返回新 datasetId |
| `data_reconcile` | 两侧 datasetId、关联键、金额列和容差，输出匹配/缺失/重复/差异 |
| `data_export` | 指定新路径写 CSV/Parquet/XLSX，返回文件和计算清单 |
| `data_status` / `data_cancel` | 长任务进度与取消 |

首版不向模型开放任意 SQL/Python。结构化操作编译成参数化查询，列名只能来自已注册 schema，函数有白名单。数据集由组件导入后注册；禁止用户表达式引用任意路径、ATTACH、INSTALL/LOAD、远程表函数和扩展。

DuckDB 的只读连接不等于文件/网络沙箱。禁用自动扩展安装/加载和不需要的外部访问；导入由受控代码完成，临时目录、内存和线程均设上限。具体配置名以锁定版本官方文档核实并用负例测试，不以 SELECT 前缀做校验。

金额使用显式 decimal 精度和舍入规则；日期格式、时区、编码、千分位、前导零、空串/null 均在导入报告展示。XLSX 公式优先读取缓存值并标记来源，没有缓存时报告“未计算”，不把公式文本当金额。禁止静默丢失解析失败行。

每条结果可追溯 sourceId + sheet + row 或导入行号。聚合结果附输入集合、计算步骤、代码/引擎版本和输入哈希，必要时提供贡献行查询，不能把一个聚合数伪装成某个原始单元格。

### 1.2 逐步方案

| 步骤 | 工作 | 出口 |
| --- | --- | --- |
| T0 | 同一关联/汇总/去重任务比较 DuckDB、Polars、现有脚本基线 | 固定 10 万/100 万行、窄/宽表、数据倾斜；记录资源和结果；选择一个主内核 |
| T1a | 受控导入、类型确认、原始行映射 | 编码、缺值、重复键、公式缓存等 30 个小型金样本精确通过 |
| T1b | 结构化变换与对账 | 一对多关联明确提示行数膨胀；重复键不能被静默合并 |
| T1c | 作业、内存/磁盘预算、取消 | 百万行任务有界执行，磁盘不足给错误，不留下已发布半文件 |
| T1d | MCP + 如意见证结果 | 原数据不改，复用已有 Office 工具整理展示 |
| T1e | 干净机器离线回放 | Excel 读取无隐式扩展下载；CSV 导出按用途处理公式注入 |

验收：金样本的行数、金额、匹配类别和来源 100% 与人工期望一致；相同输入和步骤重跑结果哈希一致（剔除声明的时间元数据）。CSV 面向表格软件导出时转义可能被当作公式的文本，并在清单记录转换；原始值在内部保留，负数数值不能被错误转成文本。

性能目标在 T0 固定机器后确定，不预报未知吞吐；至少报告 100 万行关联/汇总耗时、峰值内存、spill 大小和取消耗时。旧组件回退仍能读取版本化计算清单，已发布数据集不可变。

## 2. 本地 TTS：以完整播放体验为交付

目标：朗读所选回答、播报用户启用的任务结果，支持随时停止。建议目录 `tts-local/`、包 `ruyi_tts_local`。引擎路线首选 sherpa-onnx，具体中文声音不凭名称选定，必须比较许可、数字读法、音质和 CPU 延迟。

### 2.1 主仓与组件的拟议接口

组件候选 HTTP：`GET /health`、`GET /v1/voices`、`POST /v1/audio/speech`、`POST /v1/unload`。首版响应 WAV，文本按句切分并限制长度；每个请求含 model/voice/text/speed/requestId。停止请求的细节在 V0 冻结，不假设客户端断连就会终止推理。

登记使用 `provides.type=tts` **需要主仓新增支持**；现有代码不会因为出现该字段就自动播放。主仓须新增专用能力选择、TTS 代理、播放队列、停止按钮、会话切换取消，以及模型切换卸载。主仓生成播放 generationId，旧请求晚到时不得自动播出。

只有用户触发朗读或明确启用播报才播放；不朗读隐藏推理和内部工具日志。超长回答可选摘要/选中段落，由主仓决定文本，组件只负责合成。首版不提供声音克隆。

### 2.2 逐步方案

| 步骤 | 工作 | 出口 |
| --- | --- | --- |
| V0 | 主仓冻结能力、代理、播放/取消协议；比较可离线中文声音 | 接口文档、模型许可清单；选一 CPU 默认声音 |
| V1a | 服务、音频合成、健康检查、懒加载/卸载 | health 不加载重模型；无 Origin/Host 绕过；固定采样率和长度限制 |
| V1b | 主仓播放队列、停止、切换 | 点击停止后不再播放晚到响应；切换任务不会串音 |
| V1c | 语音测试 | 至少 100 句数字、日期、金额、缩写、多音字、中英混排；记录逐句错误 |
| V1d | 离线迁移与资源测试 | CPU 单句热态 RTF 目标 <1；停止后 300ms 内本地静音；冷首包延迟单列 |

可懂度由至少两名听者独立记录，不用同一个 ASR 自动回识别分数替代全部听评。金额/日期测试精确读法目标 ≥98%；达不到时先改规范化规则并保留原文，不让模型随意改写数字。

组件故障时主仓仍正常显示文本，播放入口显示失败原因。TTS 关闭或模型切走时卸载；回退只停用该能力，不改变对话模型和语音识别选择。
