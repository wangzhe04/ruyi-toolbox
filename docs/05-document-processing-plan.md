## 1. 场景与范围

目标：“把这批中文扫描 PDF 的表格提取出来，形成可合并的数据，并能返回原页核对。”首版输入 PDF、PNG、JPEG、TIFF；输出规范 JSON、Markdown、表格 CSV。Office 生成交给如意已有工具，首版不做 DOCX/PPTX 重排版、手写专用识别、签章鉴真或自动修正数字。

建议目录 `mcp/document-parser/`、Python 包 `ruyi_document_parser`，按 [登记约定](00-component-registry.md) 作为 stdio MCP 安装。Docling 是首选解析内核，输出先转成自己的稳定格式，避免上游对象直接成为跨组件契约。

## 2. 最小工具面（拟议，不是现有 API）

| 工具 | 输入 | 输出/行为 |
| --- | --- | --- |
| `document_parse` | 已授权绝对路径、页范围、`profile=cpu`、幂等键 | 立即返回 jobId，不在 MCP 调用中阻塞解析整本文档 |
| `document_status` | jobId | 状态、已处理/总页、警告和错误码 |
| `document_read` | documentId、页/块范围、cursor、maxChars | 有界内容、出处和续读 cursor |
| `document_export` | documentId、格式、授权输出目录 | 新文件路径、哈希、导出清单；禁止默认覆盖 |
| `document_cancel` | jobId | 请求取消，确认终止后状态才变 cancelled |

首版建议每作业最多 500 页/200 MiB，实际限额在 D0 核定；超限明确拒绝或要求选页，不静默截断。单次内容返回默认 12,000 字符、上限 32,000，完整内容保存在本地结果文件中。工具错误统一 `{code,message,retryable,details}`，不把未处理页算成成功。

## 3. 材料格式 v1

文档头包含 `schemaVersion`、`documentId`、`sourceSha256`、源文件大小、解析器/模型版本、profile、创建时间、页数、状态、warnings。documentId 绑定内容哈希及解析配置；文件位置是元数据，不以文件名作为唯一身份。

块至少包含：`blockId`、`page`（物理页从 1 开始）、`kind`、`order`、`text`、`bbox`、`confidence`、`provenance`。bbox 统一为旋转校正后页面左上角原点、0–1 归一化矩形，另存原页面尺寸和旋转变换；无法映射则为 null，不猜坐标。confidence 无可靠来源时为 null，不造百分数。

表格另存单元格 `row/col/rowSpan/colSpan/rawText` 和原始位置。清洗值作为独立字段保存，不能覆盖 rawText；跨页表格首版保留分表及候选关联，不无证据自动拼接。数字、单位、括号负数、脚注和空白单元格均保留。

资料库消费此格式；`sourceSha256 + page + blockId` 构成可验证出处。源文件改变后必须生成新版本，不让旧引用指到新文字。

## 5. 验收方法

质量不以“JSON 能解析”代替。盲测要求：页数/失败页记账 100%；返回出处定位正确率 100%；标注表格单元格文字准确率 ≥95%；标注关键数字精确匹配 ≥98%；标注相邻块阅读顺序正确率 ≥95%。按类别分别报告，不能用文字层页的高分掩盖扫描表格失败。

文字归一化只允许预先确定的空白和全半角规则，不能去掉小数点、负号、单位后再算准确。对未达标类别标记“不支持/需核对”，不默认送入自动汇总。记录字符错误率和错误原页，方便后续迭代。

性能测目标机 3 次冷启动、10 次热任务的中位数和 p95，测峰值 RSS/显存、每页耗时和包大小。D0 固定硬件后给出可接受预算；首版硬要求 CPU 完成 100 页任务不崩溃、单页失败不丢整本、取消 5 秒内确认或强制结束工作子进程。

## 6. 依赖与失败处理

模型在安装阶段预取，运行时禁止隐式下载；明确选择 OCR 后端，不把所有可选引擎打入默认包。损坏、加密、超大尺寸图片、无文字页、模型缺失、磁盘满分别返回可判别错误。

安装时先应用 G0 的目录约定澄清。解析缓存仅在组件目录内；输出到用户目录需要授权且不覆盖。升级解析器产生新缓存键；失败回退旧组件版本，旧材料可读，不原地重写旧结果。所有页级缓存和导出清单可由用户清理，不把正文写进诊断日志。
